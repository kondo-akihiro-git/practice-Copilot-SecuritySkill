# セキュリティレビュー

## 目的と適用範囲

この Skill は、Python/Django、JavaScript、TypeScript、HTML、CSS と Python/npm
依存関係を検査する。既知の依存関係脆弱性、危険な実装パターン、Django の
デプロイ設定、認証・認可などの文脈依存リスクを、異なる根拠として分けて報告する。

ユーザーが「セキュリティレビュー」「脆弱性検査」「コミット前の安全性確認」または
「Django のセキュリティ確認」を求めたときに使用する。

## 実行手順

1. 対象リポジトリの指示、対象技術、依存マニフェスト、ロックファイルを確認する。
2. プラグインに同梱する `scripts/security_scan.py` を使用し、対象リポジトリを
   `--root` で明示する。全体検査では `--mode full --django-check`、コミット前は
   `--mode pre-commit --staged` を指定する。
3. 結果 Markdown の「検査できなかった項目」を必ず確認する。ツール未導入、ネットワーク
   失敗、タイムアウトは安全の証明ではない。
4. 静的解析の検出結果をコード文脈とデータフローで再確認する。AI の結論は
   **要レビュー**として示し、CVE や確定脆弱性と混同しない。
5. 少なくとも、認証・認可（IDOR を含む）、ユーザー入力からの SQL/XSS/コマンド実行、
   アップロード/ダウンロードのパス検証、秘密情報、外部リダイレクト、Cookie/セッション、
   Django の `DEBUG`、`SECRET_KEY`、`ALLOWED_HOSTS`、HTTPS/セキュリティヘッダーを追跡する。

## 使用する自動検査

| 手段 | 根拠 | 役割 |
|---|---|---|
| pip-audit | PyPI/OSV 等の既知アドバイザリ | requirements/ロックされた Python 依存関係 |
| npm audit | npm レジストリのアドバイザリ | package-lock の JavaScript/TypeScript 依存関係 |
| Bandit | Python AST | Python の一般的な危険 API |
| Semgrep（同梱ルール） | 構文パターン | Python/Django/JS/TS/HTML の高信号パターン |
| `manage.py check --deploy` | Django 公式チェック | Django デプロイ設定（明示指定時） |

`security_scan.py` は、必要な検査ツールが見つからない場合や依存関係 DB の照会に失敗した
場合を **未実施** として記録し、終了コードを 0 にしない。`npm audit` と pip-audit は
ネットワーク上のアドバイザリを参照するため、接続できない場合も同様である。

## 重大度と報告

表示は `緊急`、`重大`、`高`、`中`、`低`、`情報`、`警告` を使う。外部ツールの
重大度は原文を保持しつつ日本語へ写像する。既知依存脆弱性は、CVSS のみで確定せず、
到達可能性・公開面・認証要否・実際の使用を確認する。自動検査の検出は根拠であり、
悪用可能性の断定ではない。

## AI レビューの制約

AI はローカル CLI から自動起動しない。認証、利用条件、料金、実行時間をリポジトリ側で
安全に保証できないためである。Copilot Chat で本 Skill を呼び出し、検査結果と対象コードを
根拠に人間が確認する。外部サービスへ秘密情報や未公開コードを送信しない。

## 除外

`node_modules`、仮想環境、キャッシュ、ビルド成果物、バイナリ、ベンダー生成物は除外する。
それらは通常自作コードではなく、検査ノイズと実行時間を増やすためである。依存関係自体は
ファイル走査では除外しても、マニフェスト/ロックファイルを監査するため見落とさない。
